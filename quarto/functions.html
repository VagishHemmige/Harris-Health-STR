# Reads the manual regimen corrections, if the file exists. Each row says: for
# this patient, between first_date and last_date (either may be blank, meaning
# open-ended), the regimen is really `regimen`. Later rows win, as later
# `replace` lines did in Stata.
read_regimen_corrections <- function(path) {
  if (!file.exists(path)) {
    return(tibble(studyid = numeric(), first_date = as.Date(character()),
                  last_date = as.Date(character()), regimen = character()))
  }
  read_csv(path, show_col_types = FALSE, col_types = cols(
    studyid = col_double(), first_date = col_date(), last_date = col_date(),
    regimen = col_character()
  ))
}

Checking one row per patient

Stata’s merge 1:1 refuses to run if a patient appears twice in either file. A join in R has no such check by default: a duplicate row would quietly give that patient two rows, and every later count and model would include them twice. This function stops with a message instead. Used by 2. Labs and baseline; the joins elsewhere state their expected relationship for the same reason.

Click to show/hide R Code 
# Stata's `merge 1:1` stops if a patient appears twice in either file. This
# does the same for a table that should have one row per patient, before it is
# joined, so a duplicate cannot silently multiply a patient's rows.
check_unique_patients <- function(data, table_name) {
  duplicated_ids <- data |>
    count(studyid) |>
    filter(n > 1)
  if (nrow(duplicated_ids) > 0) {
    stop(table_name, " has more than one row for ", nrow(duplicated_ids),
         " patient(s); it should have one row per patient.")
  }
  invisible(data)
}

Naming a regimen

Stata built the name by reshaping the day’s fills wide, sorted by drug name, and gluing drugname1 + "/" + drugname2 + ..., then trimming trailing slashes. Sorting and pasting does the same in one line. locale = "C" sorts the way Stata does, by character code.

Click to show/hide R Code 
# Joins the drugs filled on one day into a regimen name, in alphabetical order,
# as Stata did by sorting on drugname and concatenating with "/". A drug filled
# twice on the same day appears twice, as it did in Stata.
make_regimen_name <- function(drug_names) {
  str_c(str_sort(drug_names, locale = "C"), collapse = "/")
}

Applying manual corrections

In Stata each correction was a line such as

replace CurrentRegimen="<regimen>" if ((studyid==<id>) & (ARTDate>=date("<m/d/y>","MDY")))

Here the corrections are rows of a table with a patient, an optional first and last date, and the regimen. A join finds the fill dates each correction covers. When two corrections cover the same date the later one wins, as the later replace did.

Click to show/hide R Code 
# Replaces the regimen named on a fill date when a correction covers that
# patient and date. If several corrections cover the same date, the last one wins.
apply_regimen_corrections <- function(dispense_regimens, corrections) {
  matched <- corrections |>
    mutate(correction_order = row_number()) |>
    inner_join(dispense_regimens |> select(studyid, dispense_date),
               by = "studyid", relationship = "many-to-many") |>
    filter(is.na(first_date) | dispense_date >= first_date,
           is.na(last_date) | dispense_date <= last_date) |>
    group_by(studyid, dispense_date) |>
    slice_max(correction_order, n = 1) |>
    ungroup() |>
    select(studyid, dispense_date, corrected_regimen = regimen)

  dispense_regimens |>
    left_join(matched, by = c("studyid", "dispense_date"), relationship = "one-to-one") |>
    mutate(regimen = coalesce(corrected_regimen, regimen)) |>
    select(-corrected_regimen)
}

Counting pills on hand

The core of the adherence calculation (Stata Step 8):

replace CurrentDrug`counter'PillsLeft=cond((CurrentDrug`counter'CurrentDispense==30)&(CurrentDrug`counter'PillsLeft[_n-1]==0),30, ///
    max(0,CurrentDrug`counter'CurrentDispense+CurrentDrug`counter'PillsLeft[_n-1]-1)) if ...

Stata’s replace works down the rows in order, so x[_n-1] on the right is the value just computed for the row above: a running calculation. R’s vectorised functions do not work that way, so this is one of the few places a loop is the clearest code. The value is the pills available including today’s dose: a 30-pill fill covers that day and the next 29. A refill on a day with none left gives 30 rather than 29, because no pill from the old supply was used.

Click to show/hide R Code 
# Pills of one drug on hand each day of one regimen, as in Stata Step 8.
# Day 1 starts with start_pills. Each later day: a 30-pill fill when the patient
# had none left gives 30; otherwise yesterday's pills plus today's fill, less one
# pill taken, never below zero. Pills therefore build up when a patient refills
# early.
# Written as a loop because each day depends on the day before.
count_pills_on_hand <- function(pills_dispensed, start_pills, fill_size) {
  pills <- numeric(length(pills_dispensed))
  pills[1] <- start_pills
  for (day in seq_along(pills_dispensed)[-1]) {
    if (pills_dispensed[day] == fill_size && pills[day - 1] == 0) {
      pills[day] <- fill_size
    } else {
      pills[day] <- max(0, pills_dispensed[day] + pills[day - 1] - 1)
    }
  }
  pills
}

Carrying pills into a new regimen

When a patient switches from, say, Norvir/Reyataz/Truvada to Norvir/Prezista/Truvada, the Truvada and Norvir they still have count towards the new regimen. Stata did this with a loop over every pair of drug positions; here the leftover pills of matching drugs are passed in.

Click to show/hide R Code 
# On the first day of a new regimen, pills of the same drug left over from the
# previous regimen are added (less the one taken that day), once for each
# matching drug in the previous regimen, as the nested Stata loop did.
# previous_pills is NA when the drug was not in the previous regimen.
carry_over_pills <- function(pills_dispensed, previous_pills) {
  pills <- pills_dispensed
  for (leftover in previous_pills[!is.na(previous_pills)]) {
    pills <- max(0, pills + leftover - 1)
  }
  pills
}

Viral suppression on a day

The daily definition used throughout. In Stata, a missing value is larger than any number, so missing <= 400 is false; coalesce(..., FALSE) gives R the same answer where R would otherwise return NA.

Click to show/hide R Code 
# A day counts as virologically suppressed when the last viral load was at or
# below the threshold and it was either measured within the last 90 days, or the
# next one comes within 90 days and is also at or below the threshold (Stata
# Step 8). Stata treats comparisons with missing values as false; coalesce()
# does the same here.
vl_suppressed_on_day <- function(last_vl, days_since_last_vl, days_until_next_vl,
                                 next_vl, threshold, window_days) {
  suppressed <- last_vl <= threshold &
    (days_since_last_vl <= window_days |
       (days_until_next_vl <= window_days & next_vl <= threshold))
  coalesce(suppressed, FALSE)
}

Baseline comparisons

The R counterparts of tab ..., chi2, ttest and ranksum, with the options that match Stata’s defaults. Used by 7. Propensity score.

Click to show/hide R Code 
# Baseline comparison between the STR and multi-tablet groups, as the Stata
# tab ..., chi2 / ttest / ranksum commands did. Stata's chi2 has no continuity
# correction, ttest assumes equal variances and ranksum uses the normal
# approximation.
compare_categorical <- function(patients, variable) {
  counts <- table(patients[[variable]], patients$str)
  tibble(variable = variable, test = "Pearson chi-squared",
         p_value = chisq.test(counts, correct = FALSE)$p.value)
}

compare_continuous <- function(patients, variable) {
  values <- patients[[variable]]
  t_test <- t.test(values ~ patients$str, var.equal = TRUE)
  rank_test <- wilcox.test(values ~ patients$str, exact = FALSE, correct = FALSE)
  tibble(
    variable = variable,
    test = c("t-test", "Wilcoxon rank-sum"),
    p_value = c(t_test$p.value, rank_test$p.value)
  )
}

Weighted category distributions

The R counterpart of tab InitialRegimenSTR <variable> [aw=IPW], row: within each group, the weighted percentage of patients in each category. Used by 7. Propensity score.

Click to show/hide R Code 
# Weighted percentage of each group in each category: the R counterpart of
# Stata's `tab InitialRegimenSTR <variable> [aw=IPW], row`. Patients missing
# the variable or the weight are left out, as tab leaves them out.
weighted_distribution <- function(patients, variable, weight) {
  patients |>
    filter(!is.na(.data[[variable]]), !is.na(.data[[weight]])) |>
    group_by(str, category = as.character(.data[[variable]])) |>
    summarise(weight_total = sum(.data[[weight]]), .groups = "drop_last") |>
    mutate(weighted_percent = 100 * weight_total / sum(weight_total)) |>
    ungroup() |>
    transmute(variable = variable, str, category, weighted_percent)
}

Odds ratios

The R counterpart of logistic outcome InitialRegimenSTR and logistic outcome InitialRegimenSTR [pw=IPW]. A probability-weighted logistic regression in Stata reports robust (sandwich) standard errors; svyglm() with a one-stage design and the weights gives the same kind. Confidence intervals are Wald intervals, as Stata’s are. Used by 8 and 9.

Click to show/hide R Code 
# Odds ratio for an outcome comparing STR with multi-tablet regimens.
# Without weights: ordinary logistic regression (Stata: logistic y str).
# With weights: survey-weighted logistic regression, which gives the robust
# standard errors Stata reports for [pw=IPW].
odds_ratio_for_str <- function(patients, outcome, weight = NULL) {
  model_formula <- reformulate("str", response = outcome)
  model_data <- patients |> filter(!is.na(.data[[outcome]]))
  if (is.null(weight)) {
    model <- glm(model_formula, data = model_data, family = binomial())
    label <- "Unadjusted"
  } else {
    model_data <- model_data |> filter(!is.na(.data[[weight]]))
    design <- svydesign(ids = ~1, weights = reformulate(weight), data = model_data)
    model <- svyglm(model_formula, design = design, family = quasibinomial())
    label <- str_c("Weighted (", weight, ")")
  }
  # Wald confidence intervals and z-test p-values on the log-odds scale, as
  # Stata reports (svyglm's own p-values use the t distribution).
  tidy(model) |>
    filter(term == "strTRUE") |>
    transmute(outcome = outcome, analysis = label, patients = nrow(model_data),
              odds_ratio = exp(estimate),
              conf_low = exp(estimate - qnorm(0.975) * std.error),
              conf_high = exp(estimate + qnorm(0.975) * std.error),
              p_value = 2 * pnorm(-abs(estimate / std.error)))
}

## Checking one row per patient

Stata's `merge 1:1` refuses to run if a patient appears twice in either file. A join in R has no such check by default: a duplicate row would quietly give that patient two rows, and every later count and model would include them twice. This function stops with a message instead. Used by [2. Labs and baseline](02_labs_and_baseline.qmd); the joins elsewhere state their expected `relationship` for the same reason.

## Counting pills on hand

The core of the adherence calculation (Stata Step 8):

```stata
replace CurrentDrug`counter'PillsLeft=cond((CurrentDrug`counter'CurrentDispense==30)&(CurrentDrug`counter'PillsLeft[_n-1]==0),30, ///
    max(0,CurrentDrug`counter'CurrentDispense+CurrentDrug`counter'PillsLeft[_n-1]-1)) if ...
```

Stata's `replace` works down the rows in order, so `x[_n-1]` on the right is the value just computed for the row above: a running calculation. R's vectorised functions do not work that way, so this is one of the few places a loop is the clearest code. The value is the pills available *including* today's dose: a 30-pill fill covers that day and the next 29. A refill on a day with none left gives 30 rather than 29, because no pill from the old supply was used.

```{r}
#| label: count-pills-on-hand
#| eval: false
```

```{r}
#| echo: false
#| eval: true
#| output: asis
```
